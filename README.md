# hxyfront-62009 地毯修复纹样档案

给手工地毯修复工作室使用的纹样档案 + 补线库存台账（纯前端，数据存浏览器 localStorage）。

## 功能

### 纹样档案
- 录入地毯**产地、年代、结密度、材质、染色方式、破损区域**
- 上传**纹样局部标记图**（自动压缩），点击图面添加编号标记点并写说明
- **修复前 / 修复后备注**分开记录
- 档案列表**按产地筛选**，另带关键字搜索
- 档案卡片汇总该件地毯的待开工 / 占线中 / 已完工工序数

### 修复工序（补线单）
- 新增工序时从**材料色卡选补线**，下拉实时显示每张卡的库存与可开单量
- 状态机：**待开工 →（开工）占用中 →（完工）已完工**；未完工单可**撤单**
- **开工先占线**：冻结数量、不动账面库存，其他人不能重复占用
- **完工再扣库存**：从色卡账面库存真正扣减（二次确认）
- **撤单放回**：占用中的单据撤单后，占用量回到可用库存
- 可开单量不足时，开工被拒绝并提示缺口

### 材料色卡
- 每张色卡显示 **账面库存 / 占用中 / 可开单（= 账面 − 占用）**，支持出入库登记
- 色卡**改名、换色号、改色样**只影响今后；旧工序保留**开单当时的名称与色号快照**
- 库存始终按色卡身份（id）结算，与名称/色号是否改过无关
- 工序卡片对"色卡已改名/换号"给出明确提示

## 技术栈

React 19 + Vite 7 + TypeScript（严格模式），无额外 UI 框架。

## 本地运行

```bash
npm install
npm run dev      # 开发，端口 62009
npm run build    # 构建（含 tsc 类型检查）
npm run preview  # 预览生产构建
```

## 数据结构要点

- `Carpet`：档案基本信息 + `patternImage`（压缩 dataURL）+ `markers[]`（相对坐标 0~1）+ 修复前/后备注
- `ColorCard`：当前名称 / 色号 / 色样 / 单位 / 账面库存
- `Job`：`colorCardId` 关联色卡（库存结算依据），`colorName / colorCode / colorHex / unit` 为开单瞬间快照

页面右上「恢复演示数据」可重置内置样例——其中 GX-002 演示色卡由「藏青 / T-07」改名为「靛青 / IND-031」后，旧工序仍显示当时的名称和色号，库存按新色卡继续算。
